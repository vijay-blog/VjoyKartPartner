# Environment variables

Required in production:
- DB_URL
- DB_USERNAME
- DB_PASSWORD
- MYSQL_ROOT_PASSWORD
- JWT_SECRET (32+ chars, random)
- ADMIN_PASSWORD

## Delivery-partner OTP login (2Factor)

`POST /api/v1/auth/partner/send-otp` needs these. Without `TWOFACTOR_API_KEY` the endpoint
responds `503 "OTP service configuration is missing."` — never a generic HTTP 500.

Required:
- `TWOFACTOR_API_KEY=<YOUR_KEY>` — 2Factor account API key. Never commit this value.

Optional (sensible defaults are built in):
- `TWOFACTOR_OTP_TEMPLATE=<YOUR_TEMPLATE>` — custom 2Factor OTP template name. Leave unset to use
  the account's default OTP template.
- `TWOFACTOR_BASE_URL` (default `https://2factor.in`)
- `TWOFACTOR_TIMEOUT_SECONDS` (default `15`)
- `OTP_TTL_SECONDS` (default `300`)
- `OTP_RESEND_COOLDOWN_SECONDS` (default `30`)
- `OTP_MAX_VERIFY_ATTEMPTS` (default `5`)
- `OTP_MAX_SENDS_PER_HOUR` (default `5`)
- `OTP_DEV_MODE` (default `false`) — only returns the OTP in the API response when **no**
  API key is configured. Never enable in production.

The OTP itself is generated by this backend (`SecureRandom`, 6 digits), stored as a salted
SHA-256 hash in `otp_challenges` with an expiry, and sent through 2Factor's
`/{api_key}/SMS/{10-digit-phone}/{otp}[/{template}]` endpoint. 2Factor does **not** generate it,
so the provider's own AUTOGEN/VERIFY endpoints are intentionally not used.

Phone numbers are always normalized to the 10-digit Indian national format by
`com.nexamart.backend.util.PhoneNumbers` before storage or any provider call.

Optional:
- PORT
- ACCESS_TOKEN_MINUTES
- REFRESH_TOKEN_DAYS
- ADMIN_USERNAME
- ADMIN_EMAIL
- ADMIN_NAME

Never commit production credentials. The application never logs the API key, the OTP, Aadhaar
numbers, passwords or tokens — only provider HTTP status, provider status/message, a masked phone
number (`******5202`) and the correlation `ERROR_ID`.
